## 1️⃣ 네트워크 기본 개념

### 1-1. 네트워크란?

- **네트워크**: 컴퓨터, 휴대폰, 프린터, 서버 같은 기기들을 **랜선(유선)이나 전파(Wi-Fi, 무선)로 연결해서 데이터를 주고받을 수 있게 만든 것**입니다.
- 예: 학원 교실의 PC들이 같은 공유기에 연결되어 있으면, 그 PC들은 하나의 네트워크 안에 있는 것입니다.

### 1-2. 인터넷이란?

- 학원 네트워크, 회사 네트워크, 통신사 네트워크, 구글 네트워크처럼 **서로 다른 수많은 네트워크가 연결된 것**이 **인터넷**입니다.
- 그래서 인터넷을 **"네트워크의 네트워크"** 라고 부릅니다.
- 이 때문에 내 PC에서 인터넷의 서버까지 가려면 **여러 개의 네트워크와 장비를 차례로 거쳐야** 합니다.

### 1-3. 클라이언트와 서버

| 용어 | 역할 | 예 |
|---|---|---|
| **클라이언트** (client) | 서비스를 **요청**하는 컴퓨터 | 내 PC, 내 휴대폰, 내 PC에서 실행한 파이썬 코드 |
| **서버** (server) | 요청을 받아 **응답**을 돌려주는 컴퓨터 | 구글 검색 서버, 경보를 받는 서버, LLM 서버 |

- 통신은 보통 **요청(request) → 응답(response)** 순서로 일어납니다.
- 1과목에서 쓴 `requests.post(url, …)`은 **클라이언트(내 PC)가 서버에 요청을 보내는 코드**입니다.

### 1-4. 코드 한 줄이 실행될 때 일어나는 일

`requests.post(url, …)` 한 줄을 실행하면 코드에는 안 보이지만 아래 일이 일어납니다.

1. 보낼 데이터가 **작은 조각(패킷)** 으로 나뉩니다.
2. 각 조각에 **받는 쪽 주소**가 적힙니다.
3. 조각들이 **랜선/Wi-Fi → 공유기 → 인터넷의 여러 라우터 → 서버** 순서로 전달됩니다.
4. 서버가 처리한 뒤 **응답**을 같은 경로로 돌려보냅니다.
5. 내 PC가 응답을 받아 코드에 결과를 돌려줍니다.

> 🎯 **오늘 수업의 목적**: 이 보이지 않는 경로를 **명령어로 직접 관찰**하는 것입니다. 1과목은 코드가 중심이었다면, 2과목은 **명령으로 보고 → 원리를 배우고 → 문서로 남기는 것**이 중심입니다.

### 1-5. 패킷 (packet)

- **정의**: 보낼 데이터를 **작게 나눈 한 조각**. 각 패킷에는 **받는 쪽 주소**가 적혀 있습니다.
- **왜 나누나?**: 데이터를 작은 단위로 나누면 여러 경로로 전달할 수 있고, 일부가 사라져도 **그 조각만 다시 보내면** 되기 때문입니다.
- **예**: ping을 한 번 보내면 신호 하나(= 패킷 하나)가 나갑니다.

### 1-6. DNS (Domain Name System, 디엔에스)

- **정의**: `google.com` 같은 **이름(도메인)** 을 **IP 주소(숫자)** 로 바꿔 주는 시스템입니다.
- **왜 필요한가?**: 사람은 이름을 쓰지만, 컴퓨터는 **IP 주소로만 통신**할 수 있습니다. 그래서 이름을 입력하면 먼저 DNS에 물어서 IP 주소를 알아낸 뒤 통신합니다.
- 오늘 실습의 `ping google.com`에서 대괄호 안에 나오는 숫자가 DNS가 알려 준 IP 주소입니다.
- 자세한 내용은 **10/14(수)** 에 배웁니다.

## 2️⃣ 왜 배우는가 · 문제를 찾는 방법

### 2-1. 관제 현장에서 가장 많은 문의

> 📞 **"인터넷이 안 돼요."**

증상은 한 문장이지만 원인은 여러 가지입니다.

| 원인 후보 | 해당하는 층 |
|---|---|
| 랜선이 빠졌거나 Wi-Fi가 꺼짐 | 1계층 (물리) |
| 같은 망 안에서 전달이 안 됨 | 2계층 (데이터링크) |
| IP 주소 설정이 틀림 / 공유기 밖으로 못 나감 | 3계층 (네트워크) |
| 상대 프로그램으로 가는 포트가 막힘 | 4계층 (전송) |
| 이름을 IP로 못 바꿈(DNS) / 서버의 서비스가 꺼짐 | 7계층 (응용) |

### 2-2. 해결 방법: 층으로 나눠서 아래부터 확인

1. 통신 과정을 **역할별로 7개 층**으로 나눈 표준이 **OSI 7계층**입니다.
2. 아래 층이 정상이어야 위 층이 동작합니다. 예를 들어 **랜선이 빠져 있으면(1계층) IP 설정이 맞아도(3계층) 통신이 안 됩니다.**
3. 그래서 문제를 찾을 때는 **항상 아래 층(1계층)부터 차례로 확인**하고, **처음으로 안 되는 층**을 원인 후보로 봅니다.

이렇게 하면 "인터넷이 안 돼요"라는 한 문장에서 **원인이 있는 층을 좁힐 수 있고**, 어느 담당자에게 넘길지 정할 수 있습니다.

## 3️⃣ 컴퓨터가 쓰는 숫자 (비트 · 바이트 · 16진수)

오늘 화면에 나오는 `32바이트`, MAC 주소의 `A4`, Wireshark의 바이트 칸을 읽으려면 아래 세 가지가 필요합니다.

| 용어 | 뜻 | 오늘 어디서 보나 |
|---|---|---|
| **비트** (bit) | `0` 또는 `1`이 들어가는 한 칸. 가장 작은 단위 | 1계층에서 선을 타고 가는 전기 신호 하나 |
| **바이트** (byte) | 비트 **8개**를 묶은 단위. 영어 글자 하나의 크기 | ping의 "32바이트 데이터 사용", Wireshark의 패킷 길이 |
| **16진수** (hexadecimal) | `0~9`와 `A~F`, 모두 **16개 글자**로 수를 적는 방법. **1바이트를 두 자리**로 적음 | MAC 주소 `A4-B1-C2-…`, Wireshark의 초록 칸 |

### 16진수 읽는 법

- 우리가 쓰는 10진수는 0~9 열 글자를 쓰지만, 16진수는 `A=10, B=11, C=12, D=13, E=14, F=15`로 이어서 씁니다.
- 예: `A4` → A는 10이므로 `10 × 16 + 4 = 164`.
- 지금은 계산할 필요 없이 **"MAC 주소는 두 자리씩 6덩어리의 16진수로 적는다"** 는 것만 알면 됩니다.

### 주소의 크기

| 주소 | 크기 | 모양 |
|---|---|---|
| MAC 주소 | 6바이트 = 48비트 | `A4-B1-C2-D3-E4-F5` (두 자리씩 6덩어리) |
| IPv4 주소 | 4바이트 = 32비트 | `192.168.0.15` (숫자 4덩어리) |

- 자세한 내용은 10/13(화)에 배웁니다.

## 4️⃣ 네트워크 장비

| 장비 | 하는 일 | 어디에 있나 |
|---|---|---|
| **스위치** (switch) | **같은 망 안**에서 **MAC 주소**를 보고 패킷을 해당 장비로 넘김 | 교실 PC들의 랜선이 모이는 장비 |
| **라우터** (router) | **망과 망을 연결**하고, 패킷에 적힌 **받는 쪽 IP 주소**를 보고 다음 장비로 넘김 | 회사·통신사의 큰 장비 |
| **공유기** | 라우터 기능 + 여러 기기가 **인터넷 주소 하나를 나눠 쓰게** 해 주는 기능 + Wi-Fi를 **한 장비에** 합친 것 | 집·작은 사무실·학원 |
| **기본 게이트웨이** (default gateway) | **다른 망(인터넷)으로 가는 패킷을 받아서 넘겨 주는 장비**, 또는 그 장비의 주소. 보통 공유기 | 예: 학원 공유기 `192.168.1.1` |

- 라우터와 공유기의 차이: 라우터는 **망과 망을 잇고 패킷을 다음 장비로 넘기는 기능**이고, 공유기는 그 기능에 **여러 기기 연결(+Wi-Fi)** 을 더한 장비입니다.
- 내 PC에서 인터넷으로 나가는 패킷은 **항상 먼저 기본 게이트웨이로** 전달됩니다.

## 5️⃣ 데이터가 서버까지 갔다 오는 과정

`ping 8.8.8.8`을 입력했을 때의 경로입니다.

| 단계 | 어디서 | 하는 일 |
|---|---|---|
| ① | 내 PC | 신호(패킷)를 만든다 |
| ② | 기본 게이트웨이 (공유기) | 받은 패킷을 학원 밖(인터넷)으로 넘긴다 |
| ③ | 인터넷의 라우터 여러 대 | 패킷의 목적지 IP를 보고 차례로 다음 장비로 넘긴다 |
| ④ | 8.8.8.8 (구글 서버) | 신호를 받고 응답을 만든다 |
| ⑤ | 내 PC | 같은 방식으로 돌아온 응답을 받고, 걸린 시간(왕복 시간)을 표시한다 |

구간별 설명:
- ① → ②: 내 PC가 신호를 만들어 공유기에 넘김
- ② → ④: 인터넷의 라우터들이 차례로 넘겨 구글 서버까지 감
- ④ → ⑤: 구글 서버가 응답을 만들어 같은 방식으로 돌려보냄. 내 PC가 **왕복 시간**을 표시

### 8.8.8.8이란?

- **구글이 누구나 쓰도록 열어 둔 공개 DNS 서버**의 IP 주소입니다.
- 늘 켜져 있어서 **"인터넷까지 연결되는지"** 확인할 때 전 세계 관제 담당자가 많이 사용합니다.

| 보내는 곳 | 응답이 오면 알 수 있는 것 | 실습 |
|---|---|---|
| 기본 게이트웨이 (공유기) | 내 PC ~ 공유기 구간이 정상 | 3-3 |
| 8.8.8.8 (구글) | 인터넷까지 정상 | 2-2 |

## 6️⃣ OSI 7계층

### 6-1. 정의

- **OSI 7계층** (Open Systems Interconnection, 오에스아이 칠계층): 통신 과정을 **역할별로 일곱 층으로 나눈 국제 표준**입니다.
- 1계층(물리)부터 7계층(응용)까지 있고, **층마다 맡는 일이 다릅니다.**

### 6-2. 7개 층 전체표

| 층 | 이름 | 맡는 일 | 쓰는 주소 · 단위 | 오늘 확인하는 명령 |
|---|---|---|---|---|
| **7** | 응용 (Application) | 사용자가 쓰는 서비스 (웹 · 메일 · DNS) | URL, 도메인 이름 | `ping 이름` |
| **6** | 표현 (Presentation) | 암호화 · 압축 · 글자 형식을 맞춤 | - | - |
| **5** | 세션 (Session) | 대화(연결)의 시작과 끝을 관리 | - | - |
| **4** | 전송 (Transport) | 받은 데이터를 **컴퓨터 안의 어느 프로그램**에 줄지 정함 (TCP · UDP) | **포트 번호** | `netstat` |
| **3** | 네트워크 (Network) | **다른 망에 있는 상대**까지 **경로를 정해** 보냄 (라우팅) | **IP 주소** | `ipconfig`, `ping` |
| **2** | 데이터링크 (Data Link) | **같은 망 안**에서 **바로 옆 장비**로 전달 | **MAC 주소** | `ipconfig //all`, `arp -a` |
| **1** | 물리 (Physical) | 0과 1을 **전기 · 빛 · 전파 신호**로 바꿔 실제로 전달 | 없음 | 랜선 · Wi-Fi 상태 확인 |

- 외우는 순서(1→7): **물리 · 데이터링크 · 네트워크 · 전송 · 세션 · 표현 · 응용** (줄여서 "물데네전세표응")
- 실무에서는 5 · 6 · 7층을 묶어 **"응용" 하나로 부르는 TCP/IP 4계층**도 많이 씁니다.

### 6-3. 층마다 자세히

#### 1계층 · 물리
- **하는 일**: 0과 1을 전기 신호(랜선), 빛(광케이블), 전파(Wi-Fi)로 바꿔 실제로 운반합니다.
- **장비가 아니라 신호를 전달하는 매체**이며 주소가 없습니다.
- **고장 나면**: 랜선이 빠지거나 Wi-Fi가 끊겨 **아무 곳에도 ping이 안 갑니다.** PC 자체는 사용할 수 있지만 네트워크 통신은 모두 끊깁니다.
- **확인**: 랜선 · Wi-Fi 아이콘, `ipconfig` 결과의 **"미디어 연결 끊김"**

#### 2계층 · 데이터링크
- **하는 일**: **같은 망 안**에서 **MAC 주소**를 보고 바로 옆 장비에게 전달합니다. 이 일을 하는 장비가 **스위치**입니다.
- **고장 나면**: 랜선 · Wi-Fi는 연결된 것으로 보이는데 **공유기나 옆자리 PC에도 ping이 안 갑니다.**
- **확인**: `arp -a`에 **공유기의 MAC 주소가 있는지** 확인

#### 3계층 · 네트워크
- **하는 일**: **다른 망**에 있는 상대까지 **IP 주소**를 보고 경로를 정해 보냅니다. 이 일을 하는 장비가 **라우터**(학원에서는 공유기)입니다.
- **고장 나면**: 같은 교실의 공유기 · 옆자리 PC까지는 되는데 **8.8.8.8 같은 외부 서버에는 연결이 안 됩니다.**
- **확인**: `ipconfig`의 **IPv4 주소 · 기본 게이트웨이**

#### 4계층 · 전송
- **하는 일**: 컴퓨터에 도착한 데이터를 **어느 프로그램이 받을지** **포트 번호**로 정합니다.
- **고장 나면**: ping은 되는데 **특정 웹사이트나 서비스만** 안 열립니다. (포트가 막혔거나 서비스가 꺼짐)

#### 5 · 6 · 7계층 · 세션 · 표현 · 응용
- 5층: 연결의 시작과 끝을 관리 / 6층: 암호화 · 압축 · 글자 형식 / 7층: 웹 · 메일 · DNS 등 사용자가 쓰는 서비스
- **7계층 문제의 예**: `ping 8.8.8.8`은 되는데 `ping google.com`은 "호스트를 찾을 수 없습니다" → 이름을 IP로 바꾸는 DNS 단계 문제

### 6-4. 패킷을 넘기는 장비와 주소

| 층 | 패킷을 넘기는 장비 | 보고 판단하는 주소 | 어디까지 보내나 |
|---|---|---|---|
| 3 네트워크 | 라우터 (학원에서는 공유기 `192.168.1.1`) | IP 주소 (예: `192.168.100.219`) | 다른 망, 즉 외부 인터넷까지 |
| 2 데이터링크 | 스위치 (교실 PC들의 랜선이 모이는 장비) | MAC 주소 (예: `A4-B1-C2-D3-E4-F5`) | 같은 망(같은 교실) 안의 옆 장비까지 |
| 1 물리 | 장비가 아니라 매체 (랜선 · Wi-Fi 전파) | 주소 없음 | 0과 1 신호를 그대로 실어 나름 |

## 7️⃣ 실습 ① ping (2교시)

### 7-1. 실습 환경: 터미널

- **터미널**: 글자(명령어)를 입력해서 컴퓨터에 일을 시키는 창입니다.
- 이번 과목도 지금까지처럼 VS Code 아래쪽의 **Git Bash** 터미널을 씁니다. 줄 앞에 **`$`** 가 보이면 Git Bash입니다.
- 먼저 아침 과제에서 만든 폴더로 이동합니다.

```bash
cd network_zt
```

- `cd`는 **폴더를 옮기는 명령**입니다.
- ⚠️ 명령은 **문서에 적힌 그대로** 입력합니다.

### 7-2. ping이란?

- **정의**: 상대에게 "응답해 주세요"라는 신호를 보내고, **응답이 오는지**와 **걸린 시간**을 재는 명령입니다.
- ping이 쓰는 통신 방식은 **ICMP** (Internet Control Message Protocol, 아이시엠피)입니다. 웹 페이지(HTTP)와 달리 "상대가 응답하는지"만 확인합니다.
  - 보내는 것: ICMP **에코 요청**("응답해 주세요" 신호)
  - 돌아오는 것: ICMP **에코 응답**과 갔다 오는 데 걸린 시간
- **응답이 오면 알 수 있는 것**: 내 PC에서 목적지까지 패킷이 오간다 → 랜선 · 공유기 · 인터넷 구간이 모두 정상
- **응답이 와도 알 수 없는 것**: 웹사이트 · 메일 같은 **서비스가 실제로 작동하는지** → 4교시에 포트로 확인

### 7-3. 명령과 옵션

```bash
ping 8.8.8.8          # 4번 보내고 끝난다
ping -n 10 8.8.8.8    # 10번 보낸다
ping -t 8.8.8.8       # 멈출 때까지 계속 보낸다 (Ctrl + C 로 멈춤)
```

| 쓰는 것 | 뜻 |
|---|---|
| `-n 숫자` | 보낼 **횟수** (number). **주소 앞**에 씁니다 |
| `-t` | 멈출 때까지 계속 보냄 |
| `Ctrl + C` | 터미널에서 실행 중인 명령을 멈춤 |

- 🍎 맥북은 `ping -c 4 8.8.8.8`, `ping -c 10 8.8.8.8`처럼 `-c`를 씁니다.
- ⚠️ 리눅스 · 맥의 `ping` 옵션은 Windows와 다릅니다. **검색한 글이 리눅스 기준이면 Windows에서 안 될 수 있습니다.**

### 7-4. 결과 읽는 법

```
Ping 8.8.8.8 32바이트 데이터 사용:
8.8.8.8의 응답: 바이트=32 시간=34ms TTL=115
8.8.8.8의 응답: 바이트=32 시간=33ms TTL=115
8.8.8.8의 응답: 바이트=32 시간=35ms TTL=115
8.8.8.8의 응답: 바이트=32 시간=34ms TTL=115

8.8.8.8에 대한 Ping 통계:
    패킷: 보냄 = 4, 받음 = 4, 손실 = 0 (0% 손실),
왕복 시간(밀리초):
    최소 = 33ms, 최대 = 35ms, 평균 = 34ms
```

| 항목 | 뜻 | 판단 |
|---|---|---|
| `32바이트 데이터 사용` | 보내는 신호 하나에 담긴 데이터 크기 | - |
| `8.8.8.8의 응답` | 응답이 왔다 | 내 PC에서 상대까지 연결됨 |
| `시간=34ms` | 갔다가 돌아오는 데 걸린 시간(**왕복 시간**). ms(밀리초) = 1000분의 1초 | 34ms = 0.034초 |
| `TTL=115` | 응답이 도착했을 때 **남아 있던 TTL** | 같은 대상끼리만 비교 (7-5 참고) |
| `손실 = 0 (0% 손실)` | 보낸 것 가운데 **응답이 안 온 비율** | 손실이 있으면 연결이 불안정 |
| `평균 = 34ms` | 네 번의 왕복 시간 평균 | **보고서에 이 값을 적음** |

> ⚠️ **자주 하는 실수**: `시간=34ms` 하나나 `최소`/`최대`를 평균으로 적는 것. **평균은 맨 아래 `평균 =` 뒤의 숫자**입니다.

**손실률 계산**: (보낸 수 − 받은 수) ÷ 보낸 수 × 100
- 예: 4번 보내 3번 받음 → (4 − 3) ÷ 4 = 0.25 → **25% 손실**

**왜 여러 번 보내나?**
- 연결이 **계속 유지되는지**, 응답 시간이 **일정한지**, **손실이 있는지** 보기 위해서입니다.
- 시간이 비슷한 이유는 같은 목적지에 같은 경로로 가기 때문입니다. 조금씩 다른 것은 그때그때 네트워크 상황에 따른 **자연스러운 차이**입니다.
- 4번보다 **10번**을 보내면 **가끔 생기는 손실도 숫자로 잡을 수 있습니다.**
- 마지막 통계는 네 번(또는 열 번)의 결과를 요약한 것입니다: 보낸 개수 · 받은 개수 · 손실 · 평균

### 7-5. TTL (Time To Live, 티티엘)

**정의**
- 패킷이 **앞으로 거칠 수 있는 장비 수**(남은 횟수)입니다.
- 패킷이 **라우터 · 공유기를 하나 지날 때마다 1씩 줄어듭니다.**
- **0이 되면 그 패킷은 버려집니다.**
- 처음 값은 **패킷을 보낸 컴퓨터가 정합니다.**

**TTL이 3일 때의 변화**

| 위치 | 출발 | 라우터 1 | 라우터 2 | 라우터 3 |
|---|---|---|---|---|
| TTL | 3 | 2 | 1 | 0 → **버림** |

**왜 버리나?**
- 라우터 설정이 잘못되면 패킷이 `A → B → A → B …` 로 **끝없이 돌 수 있습니다.**
- 이런 패킷이 쌓이면 회선이 막히므로 **0에서 버려 정리**합니다.

**버려지면 데이터가 전부 사라지나?**
- 아닙니다. TTL이 0이 되면 **그 패킷 하나만** 사라집니다(패킷 손실). 데이터 전체가 사라지는 것은 아닙니다.
- 라우터가 패킷을 버리면 보낸 쪽에 ICMP **"TTL 초과"** 로 알립니다. 이후 처리는 보내는 방식에 따라 다릅니다.

| 보내는 방식 | 버려지면 |
|---|---|
| 웹 · 파일 (TCP, 오후 5교시) | "받았다" 확인이 안 오면 보낸 쪽이 **자동으로 다시 보냄** |
| 영상 통화 · DNS (UDP, 오후 5교시) | **자동으로 다시 보내지 않음** (필요하면 프로그램이 다시 보냄) |
| ping (ICMP) | 그 요청은 그대로 끝. **응답 없음**으로 보이고 다음 요청은 새로 보냄 |

**처음 TTL의 기본값 (운영체제마다 다름)**

| 패킷을 만드는 쪽 | 처음 TTL (흔한 기본값) |
|---|---|
| Linux · macOS | 64 |
| Windows | 128 |
| 일부 네트워크 장비 (라우터 등) | 255 |

**내 화면의 `TTL=115` 해석**
1. 8.8.8.8이 응답 패킷에 **TTL = 128**을 적어 보냅니다.
2. 돌아오는 길에 **라우터 13대**를 지나며 하나 지날 때마다 1씩 줄어듭니다. (128 − 13 = 115)
3. 내 PC 화면에 `TTL=115`가 표시됩니다.

> ⚠️ **주의**
> - ping에 보이는 TTL은 **응답한 서버가 적은 값이 돌아오는 길에 줄어든 것**입니다.
> - 기본값은 **관리자가 바꿀 수 있어서**, 처음 값과 거친 장비 수는 **짐작일 뿐**입니다.
> - TTL은 **같은 대상끼리만** 비교합니다. 작을수록 거쳐 온 장비가 많다는 뜻이지만, 시작값이 서버마다 달라서 **다른 서버끼리는 비교하지 않습니다.**

### 7-6. ping으로 문제 구간 나누기

공유기(기본 게이트웨이)와 8.8.8.8에 **따로** ping을 보내면 학원 안과 외부 중 어디가 문제인지 나뉩니다.

| 공유기에 ping | 8.8.8.8에 ping | 해석 |
|---|---|---|
| 응답 옴 | 응답 옴 | 전 구간 정상 |
| 응답 옴 | 응답 없음 | 학원 안은 정상 → **공유기 다음의 인터넷 구간**이 문제 |
| 응답 없음 | 응답 없음 | **내 PC ~ 공유기, 곧 학원 안**이 문제 |

- 공유기까지의 시간은 보통 `1~5ms`, 외부 서버(8.8.8.8)는 수십 ms입니다.

### 7-7. ping 실패 문구 두 가지

| 실패 문구 | 어디에서 멈췄나 | 먼저 확인할 곳 |
|---|---|---|
| `호스트를 찾을 수 없습니다` | **이름을 IP 주소로 바꾸는 단계**에서 멈춤 (신호를 보내기 전) | DNS |
| `요청 시간이 만료되었습니다` | IP 주소로 **신호를 보냈지만 응답이 오지 않음** | 망 중간 또는 상대 서버 |

- 학원망에 따라 `대상 호스트에 연결할 수 없습니다`가 나올 수도 있습니다. 이것도 "보냈지만 답을 못 받았다"는 같은 뜻입니다.

### 7-8. ⚠️ ping 응답이 없어도 "서버가 꺼졌다"고 단정하지 않는다

- **이유**: 보안을 위해 **ICMP에 응답하지 않도록 설정한 서버나 방화벽**이 많습니다.
- **방화벽**: 허용 · 차단 규칙으로 통신을 걸러 주는 장비 (10/15에 배움)
- **흔한 경우**: ping은 실패하는데 웹사이트는 열리는 서버
- **관제 기록에 쓰는 법**
  - ❌ "서버 다운"
  - ⭕ **"ICMP로는 확인 불가"**

## 8️⃣ 실습 ② IP 주소 · MAC 주소 · ARP (3교시)

### 8-1. 새로 나오는 주소 용어

| 용어 | 뜻 | 예 |
|---|---|---|
| **IP 주소** (Internet Protocol, 아이피) | 지금 연결된 망에서 받은 **위치 주소**. **장소가 바뀌면 바뀝니다** | `192.168.0.15` |
| **MAC 주소** (Media Access Control, 맥) | **랜카드**(PC를 망에 연결하는 부품)마다 하나씩 정해진 **고유 번호**. 장소가 바뀌어도 **그대로** | `A4-B1-C2-D3-E4-F5` |
| **기본 게이트웨이** | 우리 망에서 다른 망(인터넷)으로 가는 패킷을 받아 넘기는 장비(보통 공유기)의 주소 | `192.168.1.1` |
| **서브넷 마스크** (subnet mask) | IP 주소에서 **어디까지가 "같은 망"인지** 정하는 값. 오늘은 **이름만**, 10/13(화)에 배움 | `255.255.255.0` |
| **스위치** | 같은 망 안에서 MAC 주소를 보고 패킷을 넘기는 장비 | 교실 PC들을 잇는 장비 |
| **ARP** (Address Resolution Protocol, 에이알피) | 같은 망에서 **"이 IP의 MAC 주소가 뭐예요?"** 하고 묻는 방법 | `arp -a` |
| **이더넷** (Ethernet) | 랜선으로 기기를 잇는 **유선 연결 방식**. 2계층에서 MAC 주소로 전달 | `ipconfig`의 "이더넷 어댑터" |

### 8-2. IP 주소와 MAC 주소 비교

| | **IP 주소** | **MAC 주소** (물리적 주소) |
|---|---|---|
| 층 | 3계층 (네트워크) | 2계층 (데이터링크) |
| 모양 | 숫자 4덩어리, **점(.)** 으로 구분<br>0~255 숫자 | **16진수 6덩어리**, **하이픈(-)** 으로 구분<br>`A4-B1-C2-D3-E4-F5` |
| 누가 정하나 | 망에 접속할 때 **그 망의 공유기가 빌려 줌** | PC 안의 네트워크 부품(랜카드 · Wi-Fi 칩)을 만든 회사가 **공장에서 붙여 둔 번호** (내가 정하는 것이 아님) |
| 장소가 바뀌면 | **바뀜** (노트북을 카페로 옮기면 카페 공유기가 준 다른 값으로 바뀜) | **그대로** |
| 쓰는 범위 | **인터넷 전체** (멀리 있는 상대를 찾아갈 때) | **같은 망 안** (바로 옆 장비까지 전달할 때) |

- 한 PC에 MAC 주소가 **여러 개**일 수 있습니다. 랜 · Wi-Fi · 가상 장치마다 하나씩 있기 때문입니다. **기본 게이트웨이가 적힌 장치**가 지금 쓰는 장치입니다.
- `192.168.…`로 시작하는 주소는 보통 집 · 학원 같은 **내부망**에서 쓰는 주소입니다. (자세한 내용은 10/13)

### 8-3. `ipconfig //all`: 내 PC의 주소 확인

```bash
ipconfig //all
```

**왜 슬래시를 두 번 쓰나?**
- Windows 설명서에는 `ipconfig /all`이라고 적혀 있지만, **Git Bash에서는 `/` 하나로 시작하는 말을 폴더 경로로 바꿔 버립니다.**
- 그래서 `//all`처럼 **두 번** 써야 옵션으로 전달됩니다.
- `-n` 같은 `-`로 시작하는 옵션은 바뀌지 않아서 그대로 씁니다.
- 슬래시를 하나만 쓰면 **사용법 안내만** 나옵니다.

**결과 읽는 방법**

```
이더넷 어댑터 이더넷 2:                          ← 묶음 ①: 주소가 있음 → 이 묶음 사용
   물리적 주소 . . . . . . . : A4-B1-C2-D3-E4-F5   ← MAC 주소
   IPv4 주소 . . . . . . . . : 192.168.100.219     ← IP 주소
   기본 게이트웨이 . . . . . : 192.168.1.1         ← 게이트웨이

이더넷 어댑터 Bluetooth 네트워크 연결 2:          ← 묶음 ②: 주소 없음 → 건너뜀
   미디어 상태 . . . . . . . : 미디어 연결 끊김
```

1. 결과는 `… 어댑터 …:`로 시작하는 줄마다 **한 묶음(장치 하나)** 입니다. 묶음이 여러 개 나와도 정상입니다.
2. **기본 게이트웨이 칸에 값이 있는 묶음**이 지금 쓰는 장치입니다.
   - 학원 PC는 보통 `이더넷 어댑터`, 노트북은 `무선 LAN 어댑터 Wi-Fi` 아래를 봅니다.
   - "미디어 연결 끊김"인 묶음은 건너뜁니다.
3. 그 묶음에서 `물리적 주소` · `IPv4 주소` · `기본 게이트웨이` 세 줄을 보고서에 적습니다.

| 항목 | 뜻 | 보이는 명령 |
|---|---|---|
| IPv4 주소 | IP 주소. IPv4(아이피 브이포)는 지금 널리 쓰는 IP 주소 형식 | `ipconfig` |
| 서브넷 마스크 | 내 망의 범위를 나타내는 값 (10/13에 배움) | `ipconfig` |
| 기본 게이트웨이 | 다른 망(인터넷)으로 가는 패킷을 받아 넘기는 장비의 주소 | `ipconfig` |
| 물리적 주소 | **MAC 주소** | **`ipconfig //all`에만** 나옴 |

- 🍎 맥북은 `ifconfig en0` (IP는 `inet` 줄, MAC은 `ether` 줄), 게이트웨이는 `route -n get default` (`gateway` 줄)

**관제에서의 활용**
- 경보에 찍힌 IP가 어느 PC인지 찾을 때 이 값으로 대조합니다.
- IP는 장소가 바뀌면 바뀌지만 MAC은 장치에 정해져 있어 **같은 기기인지 확인**할 때 MAC을 봅니다.
- 다만 노트북 Wi-Fi는 개인정보 보호 때문에 MAC을 바꿔 쓰기도 하므로 **MAC만으로 단정하지 않습니다.**

### 8-4. 게이트웨이까지 ping

```bash
ping 192.168.1.1     # 자기 PC에서 찾은 기본 게이트웨이 주소를 넣는다
```

- ⚠️ 문서 예시의 `192.168.0.1`을 **그대로 입력하지 않습니다.** 8-3에서 찾은 **내 기본 게이트웨이**를 씁니다.
- 결과: 게이트웨이 평균은 보통 `1~5ms`로, 8.8.8.8의 평균보다 훨씬 짧습니다.
- **이유**: 게이트웨이는 같은 건물 안에 있고 8.8.8.8은 인터넷 건너편에 있습니다. 거리가 가깝고 거쳐 가는 장비가 적을수록 왕복 시간이 짧습니다.
- **관제에서의 활용**
  - 게이트웨이까지도 느리거나 응답이 없으면 → **우리 망 안**을 확인
  - 게이트웨이는 빠른데 바깥만 느리면 → **우리 망 바깥**을 확인

### 8-5. ARP: IP 주소로 MAC 주소를 알아내는 방법

**왜 필요한가?**
- 같은 망 안에서 패킷은 **MAC 주소**로 전달됩니다.
- 내 PC가 공유기(`192.168.1.1`)에 패킷을 보내려는데, **IP 주소는 알지만 MAC 주소는 아직 모르는** 상태입니다.
- 이때 MAC 주소를 알아내는 방법이 **ARP**입니다.

**ARP 동작 순서**

| 단계 | 내용 |
|---|---|
| ① 모름 | 내 PC가 `192.168.1.1`의 IP는 알지만 MAC 주소는 모름 |
| ② 모두에게 묻기 | "`192.168.1.1`인 장비는 MAC 주소를 알려 달라"는 요청을 **같은 망의 모든 장비**에 보냄 |
| ③ 주인만 답함 | 해당 IP를 가진 공유기만 "내 MAC 주소는 `a8-5e-45-…`"라고 응답 |
| ④ 저장 | 내 PC가 `192.168.1.1 = a8-5e-45-…`를 표에 저장하고, **다음부터는 다시 묻지 않음** |

- ④에서 저장해 둔 표가 **ARP 캐시**입니다. (IP 주소와 MAC 주소의 대응을 PC가 잠시 저장해 둔 표)

**`arp -a`로 ARP 캐시 열기**

```bash
arp -a
```

```
인터페이스: 192.168.0.15 --- 0x9
  인터넷 주소           물리적 주소           유형
  192.168.0.1           a8-5e-45-01-2b-3c     동적
  192.168.0.255         ff-ff-ff-ff-ff-ff     정적
```

| 보이는 것 | 뜻 |
|---|---|
| `-a` (all) | ARP 캐시에 저장된 줄을 **전부** 보여 줌 |
| 공유기(게이트웨이) IP 줄의 `물리적 주소` | **공유기의 MAC 주소** |
| `동적` | ARP로 **알아내서 자동으로** 적은 줄 |
| `정적` | 미리 정해져 있는 줄 |
| `ff-ff-ff-ff-ff-ff` | 특정 장비가 아니라 **같은 망 전체**를 가리키는 주소 (브로드캐스트) |

> ⚠️ `ff-ff-ff-ff-ff-ff`를 게이트웨이의 MAC 주소로 적으면 **오답**입니다.

> 🚨 **보안 포인트: ARP 스푸핑**
> 게이트웨이 IP의 MAC 주소가 **평소와 다르면**, 같은 망의 다른 장비가 가짜 ARP 응답으로 ARP 캐시를 바꾼 **ARP 스푸핑(위장 공격)** 일 수 있습니다. 관제에서는 이 값이 평소와 같은지 확인합니다.

### 8-6. 3교시 정리

| 층 | 하는 일 | 주소 · 명령 |
|---|---|---|
| 3 네트워크 | 라우터가 IP 주소로 다른 망까지 전달 | IP 주소 · `ipconfig` |
| 2 데이터링크 | 스위치가 MAC 주소로 같은 망 안에서 전달 | MAC 주소 · `ipconfig //all` |
| 2 ↔ 3 | PC가 ARP로 IP 주소에 맞는 MAC 주소를 알아냄 | ARP · `arp -a` |
| 1 물리 | 케이블이 전기 신호를 보냄 | 케이블 |

## 9️⃣ 실습 ③ 포트 번호 · netstat (4교시)

### 9-1. 포트 번호란?

- **정의**: 한 컴퓨터 안에서 **어느 프로그램에게 줄지** 정하는 번호입니다. 범위는 **0~65535**이며 **주소 뒤에 붙여** 적습니다. 예: `93.184.216.34:443`
- **왜 필요한가?**
  - 한 컴퓨터에서는 브라우저 · 메신저 · 업데이트 프로그램이 **동시에** 통신합니다.
  - IP 주소는 **어느 컴퓨터인지**까지만 알려 주므로, 그 안의 **어느 프로그램**에 보낼지는 **4계층의 포트 번호**로 구별합니다.

| | IP 주소 (3계층) | 포트 번호 (4계층) |
|---|---|---|
| 알려 주는 것 | 어느 **컴퓨터**인지 | 그 안의 어느 **프로그램**인지 |
| 예 | `93.184.216.34` | `443` (웹, HTTPS) |
| 적는 법 | `93.184.216.34:443`처럼 **`주소:포트`** 로 함께 적음 | |

### 9-2. 관제 담당자가 알아야 할 포트

| 포트 | 서비스 | 설명 |
|---|---|---|
| **22** | SSH (에스에스에이치) | 멀리 있는 서버에 접속해 명령어로 조작. 주고받는 내용이 **암호화**됨 (리눅스 서버) |
| **53** | DNS | 사이트 이름을 IP 주소로 바꿈. 인터넷을 쓸 때마다 먼저 거침 |
| **80** | HTTP | 웹 페이지를 주고받음. **암호화하지 않아** 주고받는 글자가 그대로 보임 |
| **443** | HTTPS (에이치티티피에스) | 웹 페이지를 **암호화**해서 주고받음. 주소창이 `https://`로 시작하는 요즘 웹은 거의 다 이것 |
| **3389** | RDP (알디피) | Windows **원격 데스크톱**. 외부에 열려 있으면 공격 대상이 됨 |
| **135** | RPC (알피시) | Windows가 다른 PC의 기능을 **원격으로 불러 쓸 때** 사용. 바깥에 열려 있으면 원격 공격의 통로가 됨 |
| **445** | SMB (에스엠비) | Windows **파일 · 프린터 공유**. 랜섬웨어(파일을 잠그고 돈을 요구하는 악성 코드) **워너크라이**가 2017년에 이 포트로 퍼짐 |

- **우선 외울 4개**: **22 · 53 · 80 · 443**
- **80과 443의 차이**: 암호화 여부입니다. (HTTPS의 S = Secure) 오후 7교시에서 HTTP 요청의 내용이 그대로 보이는 이유를 확인합니다.

> 🔎 **검색해서 내 말로 적는 문제 (보고서 `찾아본 것`)**
> - 포트 3389가 인터넷에 열려 있으면 어떤 위험이 있나요? → 외부에서 원격 접속을 시도(무차별 대입 등)할 수 있는 공격 대상이 됨
> - 어떤 랜섬웨어가 포트 445를 이용해 퍼졌나요? → 워너크라이(WannaCry)
> - ⚠️ 검색 결과는 영어 · 리눅스 화면이 많습니다. 내 화면(한국어 Windows)의 용어와 짝을 맞춰 읽습니다.

### 9-3. 새로 나오는 용어

| 용어 | 뜻 | 4교시에서 보는 곳 |
|---|---|---|
| **서비스** (service) | 그 포트에서 일하는 **프로그램의 종류** (443 → HTTPS) | 포트 표 |
| **netstat** (network statistics, 넷스탯) | 지금 내 PC의 **연결 목록**을 보여 주는 명령 | `netstat -n` |
| **ESTABLISHED** (이스태블리시드) | 상대와 **연결되어 대화 중**인 상태 | 상태 칸 |
| **LISTENING** (리스닝) | 내 PC가 **연결 요청을 기다리며 열어 둔** 상태 | 상태 칸 |
| **PID** (Process ID, 피아이디) | 실행 중인 **프로그램마다 붙는 번호** | `netstat -ano`의 맨 끝 칸 |
| **TCP** (Transmission Control Protocol) | 데이터를 보내기 전에 상대와 **연결을 맺고**, **받았는지 확인하며** 보내는 방식. 웹 · 메일이 사용. 오후 5교시에 자세히 | 연결 목록의 프로토콜 칸 |

**포트 번호와 PID 구별**

| | 포트 번호 | PID |
|---|---|---|
| 뜻 | 통신에서 **프로그램을 가리키는 번호** | 실행 중인 **프로그램의 번호** |
| 어디서 보나 | 주소 뒤 `:443` | `netstat -ano`의 맨 끝 칸 |

### 9-4. `netstat -n`: 지금의 연결 보기

```bash
netstat -n
```

```
활성 연결

  프로토콜  로컬 주소              외부 주소              상태
  TCP    192.168.0.15:51234     93.184.216.34:443      ESTABLISHED
```

| 칸 | 뜻 | 읽어야 하나? |
|---|---|---|
| 로컬 주소 | **내 PC 쪽** 주소. 뒤의 큰 숫자(`51234`)는 PC가 그때그때 정하는 **임시 포트** | 읽지 않음 |
| 외부 주소 | **상대 쪽** 주소. `:` 뒤 숫자로 어떤 서비스인지 알 수 있음 | **여기를 읽는다** (`443` → HTTPS) |
| 상태 | `ESTABLISHED` = 연결되어 대화 중 | |

- `-n` (numeric): 주소와 포트를 **이름 대신 숫자로** 보여 줍니다.
- 브라우저를 켜 두면 **443 줄이 여러 개** 보입니다. 줄이 너무 적으면 브라우저를 하나 열어 둔 채 다시 입력합니다.
- 관제에서는 외부 포트가 **평소 보지 못한 번호**면 그 연결을 확인 대상으로 올립니다.
- 🍎 맥북: `netstat -an -p tcp` (포트는 주소 끝 마지막 점 뒤의 숫자)

### 9-5. 연결을 만든 프로그램 찾기 (PID 추적)

**1단계**: 연결 줄 맨 끝에 PID를 붙여서 봅니다.

```bash
netstat -ano | grep ESTABLISHED
```

```
  TCP    192.168.0.15:51234    93.184.216.34:443    ESTABLISHED    8124    ← 맨 끝 숫자가 PID
```

**2단계**: 그 PID로 프로그램 이름을 찾습니다.

```bash
tasklist | grep 8124
```

```
chrome.exe     8124 Console     ← 첫 칸이 프로그램 이름
```

**옵션과 기호 설명**

| 쓰는 것 | 뜻 |
|---|---|
| `-a` (all) | 연결뿐 아니라 **LISTENING 포트까지** 전부 보여 줌 |
| `-n` (numeric) | 숫자로 보여 줌 |
| `-o` | 그 연결을 만든 프로그램의 **PID를 맨 끝에** 붙임 |
| `\|` (파이프) | 앞 명령의 **결과를 뒤 명령에 넘김** |
| `grep 글자` | 그 글자가 **들어 있는 줄만** 남김 (10/2에 본 grep) |
| `tasklist` | 실행 중인 프로그램 목록과 PID. `tasklist \| grep 8124`는 PID가 8124인 줄만 보여 줌 |

> ⚠️ **주의**
> - 예시의 `8124`를 그대로 입력하지 않습니다. **내 화면에서 읽은 PID 숫자**로 바꿉니다.
> - PID는 프로그램을 다시 켤 때마다 바뀌므로 **지금 화면의 숫자**로 찾습니다.
> - `tasklist`에서 아무것도 안 나오면 작업 관리자(`Ctrl + Shift + Esc`) → **세부 정보** 탭의 PID 열에서 찾습니다.
> - 🍎 맥북: `lsof -i -n -P | grep ESTABLISHED` (첫 칸이 프로그램 이름, 둘째 칸이 PID) → `ps -p PID숫자`

**관제에서의 활용**: 수상한 외부 연결을 발견하면 **PID → 프로그램 이름** 순서로 그 연결을 연 프로그램을 밝혀서 차단할 대상을 정합니다. 침해 대응에서 악성 프로그램을 찾는 기본 순서입니다.

### 9-6. LISTENING 포트 확인

```bash
netstat -an | grep LISTENING
```

```
  TCP    0.0.0.0:135    0.0.0.0:0    LISTENING
  TCP    0.0.0.0:445    0.0.0.0:0    LISTENING
```

- `0.0.0.0:445`: 이 PC가 가진 **모든 네트워크 주소**에서 **445번 포트**의 연결 요청을 **기다리고 있다**는 뜻입니다.
- `-an` = `-a`(all) + `-n`(numeric). **`-a`를 빼면** 기다리는 포트가 안 나와서 아무 줄도 나오지 않습니다.
- PC 설정에 따라 135 · 445가 안 보이거나 다른 번호(예: 22 · 80)가 더 보일 수 있습니다. PC마다 켜 둔 프로그램이 다르기 때문입니다.

**ESTABLISHED와 LISTENING의 차이**

| | ESTABLISHED | LISTENING |
|---|---|---|
| 의미 | 상대와 **이미 연결된** 상태 | 연결 요청을 **기다리는** 상태 |
| 4교시에서 본 예 | `…:443 ESTABLISHED` 줄 (4-2) | `0.0.0.0:445 LISTENING` 줄 (4-4) |

> 🔒 **보안 관점**
> - 열려 있는 포트(LISTENING)는 **외부에서 접속을 시도할 수 있는 지점**입니다.
> - 방화벽이 막지 않으면 다른 PC가 이 포트로 접속을 시도할 수 있어, **필요 없는 포트가 열려 있는지 보는 것**이 PC 보안 점검의 첫 단계입니다.

### 10-3. 층별로 고장 났을 때 되는 것 · 안 되는 것

| 고장 난 층 | 되는 것 | 안 되는 것 | 확인하는 법 |
|---|---|---|---|
| 3 네트워크 | 같은 교실(같은 망)의 공유기 · 옆자리 PC에 ping | 8.8.8.8 같은 외부 서버 | `ipconfig`의 IPv4 주소 · 기본 게이트웨이 |
| 2 데이터링크 | 랜선 · Wi-Fi는 연결된 것으로 보임 | 공유기 · 옆자리 PC에도 ping이 안 감 | `arp -a`에 공유기 MAC 주소가 있는지 |
| 1 물리 | PC 자체는 사용 가능 | 네트워크 통신 전부 (아무 곳에도 ping 안 감) | 랜선 · Wi-Fi 아이콘, `ipconfig`의 "미디어 연결 끊김" |

> ⚠️ **자주 틀리는 곳**: 첫 번째 증상을 "인터넷이 끊겼다(1~3계층)"로 적는 것. `ping 8.8.8.8`이 되었으므로 **아래 층은 정상**입니다.

## 1️⃣1️⃣ 캡슐화

### 11-1. 정의

- **캡슐화** (encapsulation): 보낼 데이터 앞에 **층마다 포트 · IP · MAC 정보를 붙여** 패킷을 만드는 것입니다.

```
보낼 데이터(웹 요청) → + 포트(4계층) → + IP 주소(3계층) → + MAC 주소(2계층) → 선으로 전송(1계층)
```

| 방향 | 하는 일 |
|---|---|
| **보내는 쪽** | 위(7계층)에서 아래(1계층)로 내려가며 층마다 정보를 데이터 앞에 붙여 패킷을 만듦 → **캡슐화** |
| **받는 쪽** | 아래에서 위로 올라가며 **정보를 하나씩 떼어 내고**, 알맞은 프로그램에 넘김 |
| **오후 실습** | Wireshark로 패킷 하나를 열면 이 정보들이 **층별로 나뉘어 보임** |

### 11-2. 경로에서 바뀌는 것과 안 바뀌는 것

`requests.post(url)` 한 줄이 서버까지 가는 동안:

| 오늘 배운 것 | 이 경로에서 하는 일 | 경로에서의 변화 |
|---|---|---|
| **포트 번호** (4교시) | 서버 안의 HTTPS 웹 프로그램을 가리키는 목적지 포트 | 끝까지 **그대로** |
| **IP 주소** (3교시) | 최종 서버의 주소 | 인터넷을 건너는 동안 **그대로** |
| **MAC 주소 · ARP** (3교시) | **바로 다음 장비**의 주소 | 처음엔 공유기, 라우터를 지날 때마다 **바뀜** |
| **ping · netstat** (2 · 4교시) | 경로의 일부와 현재 연결을 확인 | `ping`은 IP까지 닿는지, `netstat`은 지금의 연결 · 포트 |

#### ⭐ 도전 2-5 · ping 결과를 파이썬으로 판정 (`ping_check.py`)

**하는 일**: 응답 시간을 기준값(`LIMIT`)과 비교해서 **정상 / 느림 / 실패**로 자동 분류하는 코드입니다. 서버가 수십 대면 사람이 결과를 일일이 읽을 수 없으므로, 기준값으로 나눠 두면 `[느림]` · `[실패]` 줄만 확인하면 됩니다.

```python
LIMIT = 100                                       # 이 값(ms)을 넘으면 느리다고 본다

results = [
    {"target": "8.8.8.8", "ms": 34},
    {"target": "1.1.1.1", "ms": 120},
    {"target": "192.0.2.1", "ms": None},          # None = 답이 오지 않았다
]

for r in results:                                 # 결과를 하나씩 꺼낸다
    if r["ms"] is None:                           # ① 답이 없었으면 (맨 먼저 검사)
        print(f"[실패] {r['target']} 응답 없음")
    elif r["ms"] > LIMIT:                         # ② 기준보다 오래 걸렸으면
        print(f"[느림] {r['target']} {r['ms']}ms")
    else:                                         # ③ 그 밖에는
        print(f"[정상] {r['target']} {r['ms']}ms")
```

- 실행: `python ping_check.py` (맥북은 `python3 ping_check.py`)
- 출력: `[정상] 8.8.8.8 34ms` / `[느림] 1.1.1.1 120ms` / `[실패] 192.0.2.1 응답 없음`
- **용어**: `LIMIT`(임계값) = 느리다고 판단하는 기준 / `None` = 응답이 없어 왕복 시간이 기록되지 않은 상태
- **왜 `None` 검사가 맨 앞인가?**: 값이 `None`인 것을 숫자와 비교하면(`None > 100`) `TypeError`가 나서 프로그램이 멈추기 때문입니다.

#### 문제 3-4 · ARP 캐시 보기

```bash
arp -a
```

- 적을 것: 게이트웨이 줄의 MAC 주소 · 유형 (유형은 `동적`)
- 예시 답안 (🔍 ARP는 무엇을 알아내려고 쓰나요?): *"같은 망 안에서는 MAC 주소로 전달하므로, IP 주소만 아는 상대의 MAC 주소를 알아내려고 쓴다. 내 결과에서는 게이트웨이 192.168.x.x 줄에 MAC 주소 a8-5e-…가 있고, ARP로 알아낸 값이라 유형이 '동적'이다."*
- ⚠️ `ff-ff-ff-ff-ff-ff`를 게이트웨이 MAC으로 적는 실수가 많습니다. 그것은 같은 망 전체에 보내는 주소입니다.

#### ⭐ 도전 3-5 · 주소 모양으로 IP와 MAC 구별 (`addr_kind.py`)

**하는 일**: 주소 문자열의 **모양**(점으로 4조각인지, 하이픈으로 6조각인지)을 보고 IP인지 MAC인지 분류하는 함수입니다. 로그에 IP와 MAC이 섞여 들어올 때 자동으로 분류하는 데 씁니다.

```python
def kind(address):                                # 주소의 모양을 보고 종류를 리턴하는 함수
    if len(address.split(".")) == 4:              # 점으로 나눠 네 조각이면
        return "IP"
    if len(address.split("-")) == 6:              # - 로 나눠 여섯 조각이면
        return "MAC"
    return "모름"                                  # 둘 다 아니면

for a in ["192.168.0.15", "a8-5e-45-01-2b-3c", "ff-ff-ff-ff-ff-ff", "192.168.0"]:
    print(kind(a), a)                             # 종류와 주소를 한 줄에
```

- 실행: `python addr_kind.py` (맥북은 `python3`)
- 출력: `IP 192.168.0.15` / `MAC a8-5e-45-01-2b-3c` / `MAC ff-ff-ff-ff-ff-ff` / `모름 192.168.0`
- `"192.168.0.15".split(".")`은 `['192', '168', '0', '15']`로 나뉘고, `len()`이 조각 수를 셉니다.
- `192.168.0`은 점으로 나누면 3조각, `-`로 나누면 1조각이라 두 조건에 모두 맞지 않아 `모름`이 됩니다.
- `return`을 만나면 함수가 끝나므로 위 조건부터 차례로 검사됩니다.
- ⚠️ `len()` 없이 `address.split(".") == 4`로 쓰면 목록과 숫자를 비교하게 되어 항상 거짓이 되고 전부 `모름`이 나옵니다.

#### 문제 4-1 · 포트 사전 코드 실행 (`warmup.py`)

PORTS = {80: "HTTP", 443: "HTTPS", 53: "DNS"}

- 출력: `HTTPS` / `모름`
- **설명**: `PORTS`는 `포트 번호: 서비스 이름`을 짝지어 저장한 **사전(dict)** 입니다. `PORTS[443]`은 키 443의 값을 꺼냅니다. `.get(키, 기본값)`은 키가 **없으면 에러 없이 기본값**을 돌려줍니다.
- 예시 답안 (3389는 사전에 없는데도 에러 없이 둘째 줄이 나온 이유는?): *".get(3389, \"모름\")은 키가 사전에 없으면 에러를 내지 않고 두 번째 값인 \"모름\"을 돌려주기 때문이다. PORTS[3389]처럼 대괄호로 꺼내면 KeyError가 난다."*
- 관제에서는: 표에 없는 포트를 "모름"으로 표시해 두면 그 줄만 따로 골라 확인할 수 있습니다.

#### 문제 4-2 · 지금의 연결 보기

```bash
netstat -n
```

- 순서: ESTABLISHED 줄 하나 고르기 → **외부 주소의 `:` 뒤 숫자** 확인 → 9-2 표에서 서비스 이름 찾기
- 적을 것 예시: `외부 포트 443 → HTTPS`
- ⚠️ 로컬 주소의 `:51234` 같은 큰 숫자는 임시 번호라 읽지 않습니다.

#### 문제 4-3 · 그 연결은 어느 프로그램의 것인가

```bash
netstat -ano | grep ESTABLISHED
tasklist | grep (내 화면의 PID 숫자)
```

- 적을 것 예시: `PID 8124 → chrome.exe`
- PID는 줄의 **맨 끝 칸**, 프로그램 이름은 `tasklist` 결과의 **첫 칸**입니다.

#### 문제 4-4 · LISTENING 포트 찾기

```bash
netstat -an | grep LISTENING
```

- 적을 것: 9-2 표에 있는 LISTENING 포트 → 서비스 이름 (예: `135 → RPC, 445 → SMB`). 표에 있는 번호가 **하나도 없으면 "없음"** 이라고 적습니다.
- 예시 답안 (🔍 LISTENING과 ESTABLISHED는 무엇이 다른가요?): *"ESTABLISHED는 상대와 이미 연결되어 데이터를 주고받는 상태로, 4-2에서 본 외부 포트 443 줄이 예이다. LISTENING은 내 PC가 연결 요청을 기다리며 포트를 열어 둔 상태로, 4-4에서 본 0.0.0.0:445 줄이 예이다."*

#### 문제 4-5 · 증상으로 층 좁히기

- 정답: ① 7계층(DNS, 이름 → IP 변환) ② 1~3계층(우리 망 안) ③ 4계층 이상(그 서버의 포트나 서비스)
- 예시 답안 (증상마다 그렇게 판단한 근거는?): *"①은 숫자 주소 ping이 되어 3계층까지 정상이므로 이름을 IP로 바꾸는 7계층(DNS)이 의심된다. ②는 게이트웨이까지 응답이 없어 바깥으로 나가기 전 우리 망 안(1~3계층)이 의심된다. ③은 3계층인 ping이 되므로 그 위의 포트나 서비스가 의심된다."*

#### 찾아본 것 · 이 교시에 새로 안 것

- **찾아본 것**: 검색한 내용을 **복사하지 않고 내 말로** 적습니다.
  - 2교시: TTL이 나타내는 값, 라우터를 지날 때 바뀌는 방식
  - 4교시: 3389 포트가 열려 있을 때의 위험, 445 포트로 퍼진 랜섬웨어
- **이 교시에 새로 안 것**: 그 교시에서 **처음 알게 된 것**을 한두 가지 적습니다. (예: "ping 평균은 맨 아래 줄에서 읽는다", "기본 게이트웨이는 인터넷으로 나가는 장비의 주소이다")

### 오전 마무리

- `day01_packet_analysis.md`의 **2 · 3 · 4교시 칸에 빈 줄이 없는지** 확인합니다. (빈 줄은 그 문제로 돌아가 채움, ⭐ 줄은 비워도 됨)

## 1️⃣5️⃣ 셀프 퀴즈

먼저 스스로 답해 본 뒤, 아래 정답을 확인하세요.

1. 인터넷을 왜 "네트워크의 네트워크"라고 부르나요?
2. 패킷이란 무엇인가요?
3. IP 주소 · MAC 주소 · 포트 번호는 각각 OSI 몇 계층에서 쓰나요?
4. 문제를 찾을 때 왜 1계층부터 확인하나요?
5. ping 결과의 `TTL=115`는 무엇을 뜻하나요? 처음 값이 128이었다면 몇 대의 장비를 거쳤나요?
6. 공유기에는 ping이 되는데 8.8.8.8에는 안 됩니다. 문제는 어디에 있나요?
7. `호스트를 찾을 수 없습니다`와 `요청 시간이 만료되었습니다`는 무엇이 다른가요?
8. ARP는 왜 필요한가요? ARP 캐시는 무엇인가요?
9. `netstat -n`에서 서비스를 알려 주는 것은 로컬 포트인가요, 외부 포트인가요?
10. LISTENING 포트를 왜 점검하나요?

### 정답

1. 학원 · 회사 · 통신사 등 **수많은 네트워크가 서로 연결된 것**이기 때문입니다.
2. 보낼 데이터를 **작게 나눈 조각**이며, 받는 쪽 주소가 적혀 있습니다.
3. IP = **3계층**, MAC = **2계층**, 포트 = **4계층**
4. **아래 층이 동작해야 위 층이 동작**하기 때문입니다. 처음으로 안 되는 층을 원인 후보로 봅니다.
5. 응답이 도착했을 때 **남아 있던 TTL**입니다. 128 − 115 = **13대**를 거쳤을 것으로 **짐작**합니다. (기본값은 바뀔 수 있음)
6. **공유기 바깥의 인터넷 구간**입니다. 학원 안은 정상입니다.
7. 앞은 **이름을 IP 주소로 바꾸는 단계(DNS)** 의 실패, 뒤는 IP 주소로 **보냈지만 응답이 없는** 경우(망 중간이나 상대 서버)입니다.
8. 같은 망 안에서는 **MAC 주소로 전달**하는데, IP만 알 때 **MAC 주소를 알아내기 위해** 씁니다. ARP 캐시는 알아낸 **IP-MAC 대응을 저장해 둔 표**입니다.
9. **외부(상대) 포트**입니다. 로컬 포트의 큰 숫자는 임시 번호입니다.
10. 열려 있는 포트는 **외부에서 접속을 시도할 수 있는 지점**이기 때문입니다. 쓰지 않는 포트는 닫는 것이 관제 권고입니다.

## 1️⃣6️⃣ 용어집 (가나다순)

| 용어 | 뜻 |
|---|---|
| **게이트웨이 (기본 게이트웨이)** | 다른 망(인터넷)으로 가는 패킷을 받아 넘기는 장비(보통 공유기) 또는 그 주소 |
| **네트워크** | 기기들을 선 · 전파로 연결해 데이터를 주고받게 한 것 |
| **라우터** | 망과 망을 연결하고, IP 주소를 보고 패킷을 다음 장비로 넘기는 장비 |
| **바이트** | 비트 8개를 묶은 단위 (영어 글자 하나 크기) |
| **방화벽** | 허용 · 차단 규칙으로 통신을 걸러 주는 장비 (10/15에 배움) |
| **비트** | 0 또는 1이 들어가는 한 칸. 가장 작은 단위 |
| **서버** | 요청을 받아 응답해 주는 컴퓨터 |
| **서브넷 마스크** | IP 주소에서 어디까지가 같은 망인지 정하는 값 (10/13에 배움) |
| **서비스** | 그 포트에서 일하는 프로그램의 종류 |
| **스위치** | 같은 망 안에서 MAC 주소를 보고 패킷을 넘기는 장비 |
| **공유기** | 라우터 기능 + 여러 기기 연결(+Wi-Fi)을 한 장비에 합친 것 |
| **ARP** | 같은 망에서 "이 IP의 MAC 주소"를 묻는 방법 |
| **ARP 캐시** | ARP로 알아낸 IP-MAC 대응을 저장해 둔 표 (`arp -a`) |
| **ARP 스푸핑** | 가짜 ARP 응답으로 ARP 캐시를 바꾸는 공격 |
| **DNS** | 이름(`google.com`)을 IP 주소로 바꿔 주는 시스템 |
| **ESTABLISHED** | 상대와 연결되어 대화 중인 상태 |
| **HTTP / HTTPS** | 웹 통신 방식. HTTPS는 암호화됨 (포트 80 / 443) |
| **ICMP** | ping이 쓰는 통신 방식 (에코 요청 / 에코 응답) |
| **IP 주소** | 지금 연결된 망에서 받은 위치 주소 |
| **IPv4** | 숫자 4덩어리(점으로 구분)로 적는 IP 주소 형식 |
| **LISTENING** | 연결 요청을 기다리며 포트를 열어 둔 상태 |
| **MAC 주소** | 랜카드에 정해진 고유 번호 (같은 망 안에서 전달에 사용) |
| **netstat** | 지금 내 PC의 연결 목록을 보여 주는 명령 |
| **OSI 7계층** | 통신을 역할별로 7개 층으로 나눈 국제 표준 |
| **PID** | 실행 중인 프로그램마다 붙는 번호 |
| **ping** | 상대에게 신호를 보내 응답 여부와 걸린 시간을 재는 명령 |
| **TCP** | 연결을 맺고 받았는지 확인하며 보내는 방식 (웹 · 메일) |
| **TTL** | 패킷이 거칠 수 있는 장비 수. 장비를 지날 때마다 1씩 줄고 0이면 버려짐 |
| **UDP** | 받았는지 확인하지 않고 보내는 방식 (영상 통화 · DNS) |
| **16진수** | 0~9와 A~F 열여섯 개로 수를 적는 방법 |
| **이더넷** | 랜선으로 기기를 잇는 유선 연결 방식 |
| **캡슐화** | 층을 내려가며 층마다 정보를 앞에 붙여 패킷을 만드는 것 |
| **클라이언트** | 서비스를 요청하는 컴퓨터 |
| **터미널** | 명령어를 글자로 입력하는 창 (Git Bash) |
| **패킷** | 데이터를 작게 나눈 조각 (받는 쪽 주소가 적혀 있음) |
| **포트 번호** | 컴퓨터 안의 어느 프로그램인지 가리키는 번호 (0~65535) |
| **Wireshark** | 오가는 패킷을 붙잡아 보여 주는 프로그램 (오후에 사용) |
