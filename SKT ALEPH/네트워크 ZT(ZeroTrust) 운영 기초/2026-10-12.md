# 🌐 네트워크 첫 관찰 - OSI 7계층 핵심 정리

> 💡 **오늘의 목표**
> `requests.post(url, …)` 한 줄을 실행하면 데이터가 **내 PC → 공유기 → 인터넷 → 서버**를 거쳐 갔다 옵니다. 그 길을 **명령어로 직접 관찰**하는 첫날입니다.

> 🎯 **왜 배울까?**
> 관제 데스크 문의의 대부분은 "인터넷이 안 돼요"입니다. **어디가 문제인지 좁히는 능력**이 필요합니다.

---

## 1️⃣ 기본 용어 (택배로 이해하기)

| 용어 | 쉬운 설명 | 택배 비유 |
|---|---|---|
| 패킷 (packet) | 데이터를 작게 나눈 조각. 받는 쪽 주소가 적혀 있음 | 택배 상자 하나 |
| ping | 상대에게 "응답해 주세요" 신호를 보내고 걸린 시간을 재는 명령 | "계세요?" 하고 불러 보기 |
| DNS | `google.com` 같은 이름을 IP 주소로 바꿔 주는 시스템 | 전화번호부 |
| TTL | 패킷이 거칠 수 있는 장비 수. 장비를 지날 때마다 1씩 줄고, 0이 되면 버려짐 | 경유 가능 횟수 |

### 비트 · 바이트 · 16진수

- **비트(bit)**: 0 또는 1이 들어가는 한 칸. 가장 작은 단위
- **바이트(byte)**: 비트 8개 묶음. 영어 글자 하나 크기
- **16진수**: 0~9와 A~F로 수를 적는 법. 1바이트를 두 자리로 적음 (예: MAC 주소 `A4-B1-C2-…`)
- MAC 주소 = 6바이트(48비트), IPv4 주소 = 4바이트(32비트)

## 2️⃣ 장비 구분

| 장비 | 하는 일 |
|---|---|
| 스위치 | 같은 망 안에서 **MAC 주소**를 보고 전달 (교실 PC들을 잇는 장비) |
| 라우터 | 망과 망을 잇고, **IP 주소**를 보고 다음 장비로 넘김 |
| 공유기 | 라우터 기능 + 여러 기기 연결 + Wi-Fi를 한 상자에 담은 장비 |
| 기본 게이트웨이 | 다른 망(인터넷)으로 나가는 **문** 역할을 하는 장비의 주소 (보통 공유기) |

> 📦 **경로**: 내 PC → 공유기(기본 게이트웨이) → 인터넷의 라우터 여러 대 → 목적지 서버

## 3️⃣ ping 읽는 법

```
8.8.8.8의 응답: 바이트=32 시간=34ms TTL=115
패킷: 보냄 = 4, 받음 = 4, 손실 = 0 (0% 손실)
최소 = 33ms, 최대 = 35ms, 평균 = 34ms
```

| 항목 | 뜻 | 판단 |
|---|---|---|
| 응답이 옴 | 내 PC에서 상대까지 연결됨 | 정상 |
| 시간(ms) | 갔다 오는 데 걸린 시간 (1000분의 1초) | 보고서에 평균을 적음 |
| TTL | 도착했을 때 남은 TTL | **같은 대상끼리만** 비교 |
| 손실 | 응답이 안 온 비율 | 있으면 연결이 불안정 |

> ℹ️ **8.8.8.8이란?** 구글이 누구나 쓰라고 열어 둔 DNS 서버. 인터넷 연결 확인용으로 전 세계에서 많이 씀

### ping으로 문제 구간 나누기

| 공유기에 ping | 8.8.8.8에 ping | 뜻 |
|---|---|---|
| 응답 O | 응답 O | 전 구간 정상 |
| 응답 O | 응답 X | 학원 안은 정상, **공유기 바깥(인터넷)** 문제 |
| 응답 X | 응답 X | 내 PC ~ 공유기, 즉 **학원 안** 문제 |

> ⚠️ **주의**: ping 응답이 없어도 "서버 다운"이라고 단정하지 않습니다. 보안상 ICMP(ping)에 응답하지 않게 설정한 서버·방화벽이 많아서, 기록에는 **"ICMP로는 확인 불가"**라고 적습니다.

### TTL 더 알아보기

- 처음 TTL은 패킷을 만든 컴퓨터의 운영체제가 정함 (Linux·macOS 64 / Windows 128 / 일부 네트워크 장비 255)
- 라우터 설정이 잘못되어 패킷이 끝없이 도는 것을 막으려고, 0이 되면 버림
- 버려진 패킷은 되돌려 받지 않고, 필요하면 **보낸 쪽이 새 패킷으로 다시 보냄** (웹·파일의 TCP는 자동 재전송)

## 4️⃣ OSI 7계층

통신 과정을 **역할별로 일곱 층**으로 나눈 국제 표준입니다.

| 층 | 이름 | 맡는 일 | 키워드 |
|---|---|---|---|
| 7 | 응용 | 사용자가 쓰는 서비스 | 웹·메일·DNS |
| 6 | 표현 | 암호화·압축·글자 형식 맞춤 | |
| 5 | 세션 | 연결의 시작과 끝 관리 | |
| 4 | 전송 | 컴퓨터 안의 **어느 프로그램**에 줄지 | **포트 번호** |
| 3 | 네트워크 | 다른 망까지 경로를 정해 보냄 | **IP 주소** |
| 2 | 데이터링크 | 같은 망 안에서 바로 옆 장비로 전달 | **MAC 주소** |
| 1 | 물리 | 0과 1을 전기·빛·전파 신호로 보냄 | 랜선·Wi-Fi |

> 🔑 **핵심 원칙**: 아래 층이 동작해야 위 층이 동작합니다. 그래서 진단은 **항상 아래 층(1계층)부터** 확인합니다.
> (실무에서는 5·6·7층을 묶어 "응용" 하나로 부르는 TCP/IP 4계층도 많이 씀)

## 5️⃣ 세 가지 주소 비교

| | MAC 주소 | IP 주소 | 포트 번호 |
|---|---|---|---|
| 층 | 2계층 | 3계층 | 4계층 |
| 역할 | 같은 망의 **바로 옆 장비** 찾기 | **멀리 있는 컴퓨터** 찾기 | 컴퓨터 안의 **프로그램** 찾기 |
| 정하는 사람 | 랜카드 제조사가 공장에서 부여 | 공유기가 빌려 줌 | 서비스마다 정해져 있음 |
| 장소가 바뀌면 | 그대로 | **바뀜** | - |
| 모양 | `A4-B1-C2-D3-E4-F5` | `192.168.0.15` | `:443` |

> 🏠 **비유**: IP = 아파트 주소 / 포트 = 호수 / MAC = 바로 옆집까지 가는 길 안내

### ARP란?

같은 망에서 **"이 IP를 가진 장비의 MAC 주소가 뭐예요?"** 하고 묻는 방법입니다.

1. PC가 공유기 IP(192.168.1.1)는 알지만 MAC은 모름
2. 교실의 모든 장비에게 "192.168.1.1 누구야?" 하고 물음
3. 공유기만 "나야, 내 MAC은 a8-5e-45-…" 하고 답함
4. 답을 표(**ARP 캐시**)에 저장해 두고 다음부터는 묻지 않음

> 🚨 게이트웨이 줄의 MAC이 평소와 다르면 **ARP 위장 공격**을 의심합니다.

## 6️⃣ 명령어 모음

| 하고 싶은 일 | 명령어 |
|---|---|
| 연결되는지 확인 | `ping 8.8.8.8` |
| 열 번 보내기 | `ping -n 10 8.8.8.8` |
| IP·게이트웨이·MAC 보기 | `ipconfig //all` |
| 공유기 MAC 보기 (ARP 캐시) | `arp -a` |
| 내 PC의 현재 연결 보기 | `netstat -n` |
| 연결을 만든 프로그램 찾기 | `netstat -ano` → `tasklist \| grep PID번호` |
| 열려 있는(기다리는) 포트 보기 | `netstat -an \| grep LISTENING` |

> ⚠️ **Git Bash 주의**: `ipconfig /all`이 아니라 **`ipconfig //all`** 처럼 슬래시를 두 번 씁니다. `/` 하나로 시작하는 말은 폴더 경로로 바뀌기 때문입니다. (`-n` 같은 `-` 옵션은 그대로)

### ipconfig //all에서 찾을 세 값

```
이더넷 어댑터 이더넷 2:
   물리적 주소 . . . . . . . : A4-B1-C2-D3-E4-F5   ← MAC 주소
   IPv4 주소 . . . . . . . . : 192.168.100.219      ← IP 주소
   기본 게이트웨이 . . . . . : 192.168.1.1          ← 게이트웨이
```

- 어댑터가 여러 개 나오면 **기본 게이트웨이 칸에 값이 있는 묶음**이 지금 쓰는 장치
- "미디어 연결 끊김"이 적힌 묶음(예: 블루투스)은 건너뜀
- 맥북은 `ifconfig`

## 7️⃣ 포트 번호 · netstat

### 꼭 외울 포트 4개

| 포트 | 서비스 | 쓰임 |
|---|---|---|
| 22 | SSH | 멀리 있는 서버에 접속해 조작 (암호화) |
| 53 | DNS | 사이트 이름을 IP로 바꿈 |
| 80 | HTTP | 웹 페이지 (암호화 X, 글자가 그대로 보임) |
| 443 | HTTPS | 웹 페이지 (암호화 O), 요즘 웹은 거의 이것 |

### netstat 읽는 법

```
프로토콜  로컬 주소             외부 주소             상태
TCP      192.168.0.15:51234   93.184.216.34:443    ESTABLISHED
```

- **로컬 주소**: 내 PC 쪽. 뒤의 큰 숫자는 그때그때 정하는 임시 포트
- **외부 주소**: 상대 쪽. `:` 뒤 숫자로 어떤 서비스인지 앎 (443 = HTTPS)
- **ESTABLISHED**: 이미 연결되어 대화 중인 상태
- **LISTENING**: 연결 요청을 기다리며 문을 열어 둔 상태
- **PID**: 실행 중인 프로그램마다 붙는 번호 (`netstat -ano` 맨 끝 칸)

> 🔒 **보안 관점**: 열린 포트(LISTENING)는 외부에서 접속을 시도할 수 있는 지점이라 **쓰지 않는 포트는 닫는 것**이 관제 권고입니다.

## 8️⃣ 증상으로 문제 층 좁히기

| 증상 | 문제가 난 층 | 확인 방법 |
|---|---|---|
| 랜선·Wi-Fi 끊김, 어디에도 ping 안 감 | 1계층 (물리) | 랜선·Wi-Fi 아이콘, "미디어 연결 끊김" |
| 공유기·옆자리 PC에도 ping 안 감 | 2계층 (데이터링크) | `arp -a`에 공유기 MAC이 있나 |
| 공유기는 되는데 8.8.8.8은 안 됨 | 3계층 (네트워크) | `ipconfig`의 IPv4·게이트웨이 |
| `ping 8.8.8.8`은 되는데 이름으로는 안 됨 | 7계층 (DNS) | |
| ping은 되는데 웹사이트 하나만 안 열림 | 4계층 이상 | 포트가 막혔거나 서비스가 꺼짐 |

> 🪜 **확인 순서**: 케이블·포트 연결(1) → 스위치 포트 상태(2) → ping(3) → 포트 연결(4) → 서비스 응답(7)

## 9️⃣ 캡슐화

보낼 데이터 앞에 **층마다 정보를 하나씩 붙여** 패킷을 만드는 것입니다.

```
웹 요청 → +포트(4계층) → +IP 주소(3계층) → +MAC 주소(2계층) → 선으로(1계층)
```

| | 하는 일 |
|---|---|
| 보내는 쪽 | 위에서 아래로 내려가며 층마다 정보를 앞에 붙임 (**캡슐화**) |
| 받는 쪽 | 아래에서 위로 올라가며 하나씩 떼어 내고 알맞은 프로그램에 넘김 |

> 📦 택배 상자를 **겹겹이 포장**하는 것과 같습니다. 오후에는 Wireshark로 이 정보가 층별로 나뉘어 보이는 것을 직접 확인합니다.
